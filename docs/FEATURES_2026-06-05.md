# GhostShell — Feature Build 2026-06-05 (7-feature hardening epic)

Living spec for the seven-feature pass that strengthens anti-detect, captcha
resistance, automation realism, and in-browser work. Each feature is built as a
full cycle: **tech-spec → implementation → post-audit → bug-fix → tests**.

Layer model (why each feature exists): detection/blocking happens on three
layers — **network (IP) → behavior → fingerprint**. Most captchas are layers 1–2,
not the fingerprint. The features are ordered by impact on the real workload
(Google ad-work over proxies).

---

## Feature #1 — IP-reputation pre-flight + enforcement

### Problem
A datacenter proxy IP (asocks → Datacamp AS212238) triggered Google's
network-level "this network is blocked" page — **before** any fingerprint check.
The product already classifies `IpType` (datacenter/residential/mobile via
ip-api in `HttpProxyTester`) and stores it on `Proxy`, but **does nothing with
it**: a burned datacenter IP launches silently and the user only finds out when
Google walls them.

### Goal
Turn the existing IP signal into an actionable **reputation score + gate**:
- Score each proxy 0–100 (clean→burned) from signals we already have, plus an
  optional pluggable fraud-score provider (IPQualityScore) that no-ops without a
  key.
- At launch, evaluate the assigned proxy and **warn or block** per policy, with a
  clear notification — so a burned IP never silently wastes a run.

### Files
- `Core/Models/ProxyReputation.cs` *(new)* — `ProxyReputationReport`,
  `ReputationBand { Clean, Suspect, Burned }`.
- `Core/Services/IProxyReputationService.cs` *(new)* — service + `IIpReputationProvider`
  abstraction + `ExternalReputation` record.
- `Runtime/Diagnostics/ProxyReputationService.cs` *(new)* — deterministic scoring
  (pure, testable) + async wrapper that folds in the external provider.
- `Runtime/Diagnostics/IpReputationProviders.cs` *(new)* — `NullIpReputationProvider`
  (default, no key) + `IpQualityScoreProvider` (HTTP, enabled only with a key).
- `Core/Services/ISettingsService.cs` — add `SettingsKeys.ProxyReputationGate`
  (`off|warn|block`, default `warn`) and `ProxyReputationIpqsKey`.
- `Runtime/Browser/BrowserLauncher.cs` — evaluate at launch; warn (notification)
  or block (throw) per policy; always log the band.
- `App/App.xaml.cs` — DI registration.
- `tests/.../Diagnostics/ProxyReputationServiceTests.cs` *(new)*.

### API
```csharp
public enum ReputationBand { Clean, Suspect, Burned }

public sealed record ProxyReputationReport(
    int Score,                       // 0 clean … 100 burned
    ReputationBand Band,
    IpType IpType,
    IReadOnlyList<string> Reasons,   // human-readable contributing signals
    string Recommendation);          // one-line actionable guidance

public interface IProxyReputationService
{
    // Pure, synchronous score from already-probed proxy fields.
    ProxyReputationReport Evaluate(Proxy proxy);
    // Async: same, plus an optional external fraud-score lookup.
    Task<ProxyReputationReport> EvaluateAsync(Proxy proxy, CancellationToken ct = default);
}

public interface IIpReputationProvider
{
    bool IsEnabled { get; }
    Task<ExternalReputation?> LookupAsync(string ip, CancellationToken ct = default);
}
public sealed record ExternalReputation(int FraudScore /*0-100*/, bool IsProxy, bool IsVpn, string? Source);
```

### Scoring (deterministic)
Base by `IpType`: Residential 10 · Mobile 5 · Datacenter 60 · Unknown 30.
Modifiers: ISP/ASN matches a hosting/VPN keyword (+25); `Health` Critical (+20) /
Warning (+10); external provider fraud score blended in (max of heuristic and
provider score when provider enabled). Clamp 0–100.
Bands: `<30 Clean` · `30–64 Suspect` · `≥65 Burned`.
(asocks/Datacamp datacenter → 60 + 25 keyword = **85 → Burned**, as observed.)

### Gate (BrowserLauncher)
After resolving the proxy: `EvaluateAsync`. Log band at INFO. Then by
`ProxyReputationGate` policy:
- `off` — nothing beyond the log.
- `warn` *(default)* — `Burned` posts a `warning` notification, launch proceeds.
- `block` — `Burned` throws `InvalidOperationException` (launch aborted with a
  clear message); `Suspect`/`Clean` proceed.
Fail-open on any evaluation error (never block a launch because scoring threw).

### Estimate
~1 day. Pure .NET, no Chromium rebuild. Low risk (fail-open, default `warn`).

## Feature #2 — Behavioral humanization v2

### Problem
The `goodmedika` run fired four near-identical Google searches in minutes —
a textbook bot cadence — and the trusted-input layer, while `isTrusted=true`,
still moves the cursor with **two** `mouseMoved` events (a jittered offset then
dead-centre) and types with a **uniform** per-key delay. reCAPTCHA/Turnstile and
Google's network defense score mouse trajectories and keystroke dynamics; a
2-point teleport + uniform typing reads as automation even with a clean
fingerprint.

### Goal
Make the cursor and keyboard behave like a person: curved multi-point mouse
paths with overshoot+settle and ease-in-out velocity, Gaussian keystroke timing
with word-boundary pauses and occasional typo+correction, momentum scrolling
with reading dwell, and a stable per-profile "persona" (typing speed / typo rate
/ curvature) so a profile is consistent run-to-run but distinct from its peers.

### Files
- `Runtime/Scripts/HumanBehavior.cs` *(new, pure & testable)* — `BehaviorPersona`
  (`ForProfile(name)` deterministic), `HumanTiming` (Box-Muller Gaussian,
  `NextDelay`, `KeystrokeDelayMs`), `MousePath.Generate` (cubic Bézier +
  overshoot/settle, ease-in-out per-point delays), `MousePoint`.
- `Runtime/Browser/SeleniumBrowserSession.cs` — track `_lastMouseX/Y`; dispatch
  the generated path in `TrustedHoverAsync`/`TrustedClickAsync`; Gaussian
  keystroke cadence + typo injection in `TrustedTypeAsync`.
- `Runtime/Scripts/Humanizer.cs` — scroll v2 (momentum + reading dwell via
  HumanTiming); idle/hover delays via Gaussian.
- `tests/.../Scripts/HumanBehaviorTests.cs` *(new)*.

### Design notes
- **Pure core**: all randomness flows through an injected `Random`, so paths and
  timings are unit-testable (endpoint exactness, point count, non-negative
  delays, persona stability/﻿variety, Gaussian within bounds).
- **Persona** = stable FNV hash of the profile name → seeded RNG → SpeedFactor
  (0.7 fast … 1.4 slow), TypoRate (1–5%), curvature (10–22%). Same profile →
  same persona every launch.
- **Cursor continuity**: the session remembers the last cursor position, so each
  move starts where the previous ended (no teleports between actions).
- **Cost-bounded**: total path time ~120–420 ms; typo rate low; never slows the
  happy path meaningfully.

### Estimate
~1 day. Pure .NET; no Chromium rebuild. Medium risk (touches the hot input path)
— mitigated by keeping the pure math separate + heavily tested and the dispatch
fail-safe (falls back to direct move on any error).

## Feature #3 — Multi-provider captcha solver

### Problem
`ICaptchaSolver` + `TwoCaptchaSolver` existed, but only `ManualCaptchaSolver`
was wired as the registered solver — 2captcha was dead, there was no CapSolver,
no Turnstile / reCAPTCHA-v3 / "sorry"-interstitial detection, and no provider
routing or metrics.

### Goal
A provider router that detects the captcha once and routes to the best
configured solver (CapSolver → 2captcha → manual), recognises modern challenge
types, refuses unsolvable network-block interstitials (so the caller rotates IP
instead of burning credits), and tracks per-provider success/failure. Plus a
`solve_captcha` script step that honours an explicit kind.

### Files
- `Core/Services/ICaptchaSolver.cs` — default-impl `IsAutomated` + `CanHandle(kind)`.
- `Runtime/Scripts/CaptchaDetect.cs` *(new)* — shared kind detection (reCAPTCHA
  v2/v3, hCaptcha, Turnstile, Google "sorry"), sitekey/action extraction, token
  injection (incl. `cf-turnstile-response`).
- `Runtime/Scripts/CapSolverSolver.cs` *(new)* — CapSolver createTask/getTaskResult;
  reCAPTCHA v2/v3 + hCaptcha + Turnstile; key via `GHOSTSHELL_CAPSOLVER_KEY`.
- `Runtime/Scripts/CaptchaSolverRouter.cs` *(new)* — composite `ICaptchaSolver`;
  preference order, manual fallback, "sorry" refusal, metrics.
- `Runtime/Scripts/TwoCaptchaSolver.cs` — capability hints.
- `Runtime/Scripts/ScriptRunner.cs` — `solve_captcha` step now takes an explicit
  `kind`.
- `App/App.xaml.cs` — register router as `ICaptchaSolver`; env-driven keys.
- `tests/.../Scripts/CaptchaSolverRouterTests.cs` *(new)*.

### Estimate
~1.5 days. Pure .NET; no rebuild. API solvers no-op without a key (graceful).
